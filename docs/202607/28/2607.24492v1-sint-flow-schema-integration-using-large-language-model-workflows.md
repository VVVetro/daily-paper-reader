## 摘要
模式集成的目标是，给定一组输入模式或表，推导出一个全局统一模式，该模式能够以连贯的方式表示所有输入表的概念、属性和关系。本文提出了SINT-Flow，这是一个由五个基于LLM的运算符组成的模式集成框架，这些运算符可以组合成工作流，以执行完全自动化的端到端模式集成。与现有方法相比，SINT-Flow能够处理包含描述多个实体类型的属性的非规范化源表。在模式集成过程中，这些表被分解为单独的实体特定关系。为了评估SINT-Flow，我们引入了SINT-Bench，这是一个模式集成基准，包含10个模式集成任务，总计93个关系表，包括描述多种实体类型的表。我们使用GPT-5.2以及开源模型Qwen-3.6-27B作为替代骨干模型来评估SINT-Flow。使用这些模型，SINT-Flow在实体类型检测上达到了至少96%的F1分数，属性检测上达到了85%，模式映射上达到了83%。此外，我们进行了消融研究，以证明所采用的自一致性策略以及将审查循环纳入模式匹配运算符的有效性。

## Abstract
The goal of schema integration is, given a set of input schemata or tables, to derive a global, unified schema that is able to represent the concepts, attributes, and relationships of all input tables in a coherent fashion. This paper presents SINT-Flow, a schema integration framework composed of five LLM-based operators that can be combined into workflows to perform fully automated, end-to-end schema integration. In contrast to existing approaches, SINT-Flow can process denormalized source tables that contain attributes describing multiple entity types. During the schema integration process, these tables are decomposed into separate entity-specific relations. To evaluate SINT-Flow, we introduce SINT-Bench, a schema integration benchmark comprising 10 schema integration tasks consisting of altogether 93 relational tables, including tables that describe multiple types of entities. We evaluate SINT-Flow using GPT-5.2 as well as the open-weight model Qwen-3.6-27B as alternative backbone models. Using these models, SINT-Flow achieves F1 scores of at least 96% for entity-type detection, 85% for attribute detection, and 83% for schema mapping. Furthermore, we perform an ablation study to prove the utility of the applied self-consistency strategy as well as the inclusion of a review loop into the schema matching operator.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题定义**：模式集成（Schema Integration）要求在给定一组输入表或模式的前提下，推导出一个全局统一的模式，该模式能连贯地表示所有输入表中的概念、属性和关系。
- **现有方法不足**：
  - 早期方法（1980-1990s）多为半自动，依赖人工干预。
  - 2000年代的概率/统计方法可自动化，但无法处理描述**多个实体类型**的非规范化表（denormalized tables），即一表中混合了不同实体的属性（如事件和场地混合在一张表中）。
  - 2025年初步的LLM方法能发现层级集成模式，但仍未实现按实体类型拆分输入表。
- **本文目标**：利用LLM工作流实现**全自动、端到端**的模式集成，特别针对包含多实体类型的非规范化源表，将其拆解为按实体划分的关系，并输出统一的集成模式。
- **意义**：填补自动模式集成中实体类型检测与表拆分的空白，提供开源基准和可复现框架，支持托管模型和本地开源模型两种场景，满足数据隐私需求。

## 2. 方法论：核心思想、技术细节与算法流程

### 2.1 核心思想
- 将模式集成任务分解为五个 **LLM-based 运算符**（Operator），这些运算符可按不同顺序组合成**工作流**。
- 每个运算符利用LLM的语义理解能力完成特定子任务，并通过**自一致性策略**（self-consistency, 多次运行取多数投票）和**审查循环**（review loop）提升输出稳定性与准确性。

### 2.2 五个运算符

1. **Table Splitting Operator**（表拆分运算符）
   - 输入：一组原始表 \( T \)
   - 输出：每个表按实体类型拆分后的**实体类型表集合** \( S_{TE} \)，每列归属到对应实体类型。
   - 规则：每个实体类型至少关联3个列，否则不生成。通过LLM内置工具验证列数，并使用后拆分检查确保所有列被分配。
   - 示例：输入三个表（包含Show、Theater、Event、Venue等实体），输出按实体拆分的表（如Show表、Theater表等）。
   - 关键：**不依赖函数依赖发现**，直接利用LLM背景知识和示例行推断属性所属实体。

2. **Schema Matching Operator**（模式匹配运算符）
   - 输入：实体类型表对（或原始表对）
   - 输出：列之间的**对应关系** \( Corr \) 以及基于对应关系形成的**属性组** \( AG \)。
   - 流程：逐对输入表，LLM返回匹配的列对。之后使用**后匹配审查循环**（Algorithm 1）来剔除假阳性匹配，确保属性组合并的正确性。
   - 审查算法：对每个匹配对，按四种情况处理（两列均无组、一列有组、两列分属不同组），调用LLM确认是否真正匹配或合并组。

3. **Table Grouping Operator**（表分组运算符）
   - 输入：所有实体类型表 \( T_E \)
   - 输出：按实体类型分组，每组包含描述相同实体的表，并命名组名（如Event组、Venue组）。
   - 验证：检查表不重复分配，缺失的表由LLM补充。

4. **Attribute Merging Operator**（属性合并运算符）
   - 输入：各实体类型的属性组 \( AG_E \)
   - 输出：每个实体类型的**中间集成模式** \( IIS_E \) 以及输入列到集成属性的**映射** \( M \)。
   - 任务：从每个属性组中选出一个代表性属性作为集成属性，形成中间模式。

5. **Integrated Schema Output Operator**（集成模式输出运算符）
   - 固定在工作流末尾。
   - 任务：
     - 移除实体类型间冗余属性（如Event模式中删除venue和address，因为它们属于Venue模式）。
     - 引入标识符（如venue_id）及外键连接实体类型。
     - 输出最终集成模式 \( IS_E \)、外键、所有输入列的映射 \( M_{S_{TE} \to IS_E} \)。
   - 验证：检查属性是否完全分配、实体类型模式是否冗余。

### 2.3 三种工作流（Operator组合顺序）

1. **Workflow 1: Entity Type Detection on Input Tables**  
   顺序：Table Splitting → Schema Matching → Table Grouping → Attribute Merging → Schema Output  
   特点：先逐表检测实体类型，再匹配列，最后分组合并。

2. **Workflow 2: Implicit Schema Matching**  
   顺序：Table Splitting → Table Grouping → Attribute Merging → Schema Output  
   特点：省略Schema Matching运算符，将匹配与合并合并为一个步骤，不显式输出列对应关系。

3. **Workflow 3: Entity Type Detection on Integrated Table**  
   顺序：Schema Matching → Attribute Merging → Table Splitting → Schema Output  
   特点：先在所有输入表上执行匹配和合并得到一个集成表（不分实体），然后对集成表进行实体类型拆分。

### 2.4 自一致性策略（Self-Consistency）
- 每个运算符运行3次（temperature设为高值），然后基于多数投票或共现频率构建一致输出。
- 适用于Schema Matching、Attribute Merging、Schema Output（直接多数投票）。
- 对于Table Splitting和Table Grouping，统计属性/表的共现频率，如果共现超过半数则归为一组。

## 7. 优点

1. **全自动化、端到端**：无需人工干预，从原始表直接输出集成模式与映射。
2. **处理多实体非规范化表**：首次实现按实体类型拆分列，生成外键标识符，实现规范化集成。
3. **模块化工作流设计**：五个运算符可灵活组合，便于适应不同场景和模型。
4. **鲁棒性提升策略**：自一致性（3次投票）和审查循环显著减少LLM的不稳定性。
5. **同时评估托管与开源模型**：覆盖数据隐私受限场景。
6. **开源基准与代码**：SINT-Bench及所有代码公开，便于复现和后续研究。
7. **详细的误差分析**：揭示了各运算符的错误贡献，指导未来优化方向。

## 8. 不足与局限

1. **未处理实例级变换**：仅基于模式（列名、少量示例行），不进行实体消歧或值转换，依赖原始数据质量。

3. **LLM输出不稳定**：即使使用自一致性，仍有随机性（标准差在0.08左右），成本较高（多次调用）。
4. **基准规模有限**：SINT-Bench仅10个任务93张表，现实场景异构性可能更复杂；未覆盖数据仓库或超大规模数据湖。
