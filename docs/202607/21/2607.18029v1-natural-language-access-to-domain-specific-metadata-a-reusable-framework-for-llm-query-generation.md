## 摘要
研究人员需要回答关于领域特定档案内容的临时性问题，但往往缺乏编写结构化元数据查询的专业知识。我们展示了，当领域词汇和语义被捕获在精心设计的Web本体语言（OWL）本体中时，大型语言模型（LLM）可以零样本生成准确的结构化查询，无需微调、检索增强或多智能体编排。我们提出了自然语言知识图谱查询（NLKGQ）系统，这是一个框架和开发流程，允许对这些档案中的元数据进行自然语言访问。该框架包括一个帮助研究人员提出自然语言问题的Web界面，一个领域无关的驱动程序通过LLM将问题转换为SPARQL，并针对知识图谱执行。开发流程始于在正式的OWL本体中捕获领域词汇和语义。然后，领域特定代码从档案源中提取元数据，并将其导入由本体定义的知识图谱中。两者都设计为跨领域可复用。我们在来自大规模神经影像研究档案的元数据上展示了该系统，评估了多个LLM和本体表示。最佳配置在与领域专家共同开发的胜任力和回归问题集上达到了100%的准确率。对八种本体表示的消融研究表明，可读的实体名称和语义注释是准确性的主导因素，其重要性超过模型选择或提示工程。我们还将SPARQL与自动生成的SQL数据库作为查询后端进行了比较，表明OWL的结构化特征在LLM驱动的查询生成中比SQL DDL具有显著优势。我们的演示领域还需要在适度的机构硬件上使用本地LLM，以解决人类受试者数据的隐私问题。

## Abstract
Researchers need to answer ad-hoc questions about the contents of domain-specific archives but often lack the expertise to write structured queries on the metadata. We show that when domain vocabulary and semantics are captured in a well-designed Web Ontology Language (OWL) ontology, Large Language Models (LLMs) can generate accurate structured queries zero-shot, without fine-tuning, retrieval augmentation, or multi-agent orchestration. We present the Natural Language Knowledge Graph Query (NLKGQ) system, a framework and development process that enables natural language access to metadata in such archives. The framework includes a web interface that helps researchers pose natural language questions, which a domain-agnostic harness translates to SPARQL via an LLM and executes against a knowledge graph. The development process begins with capturing domain vocabulary and semantics in a formal OWL ontology. Domain-specific code then extracts metadata from archive sources and imports it into a knowledge graph defined by the ontology. Both are designed for reuse across domains. We demonstrate the system on metadata derived from a large-scale neuroimaging research archive, evaluating multiple LLMs and ontology representations. The best configurations achieve 100% accuracy on a competence and regression question set developed with domain experts. An ablation study across eight ontology representations reveals that readable entity names and semantic annotations are the dominant factors in accuracy, more significant than model choice or prompt engineering. We also compare SPARQL to an auto-generated SQL database as query backends, showing that OWL's structural features provide a substantial advantage over SQL DDL for LLM-driven query generation. Our demonstration domain also requires local LLMs on modest institutional hardware to address privacy concerns for human subject data.

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程
### 核心思想
- 领域知识以高质量 OWL 本体作为“单一真相源”。该本体并非被动接受，而是**主动设计为 LLM 友好型**——通过可读的实体名称、语义注释（`rdfs:comment`、`rdfs:label`、`skos:altLabel`）、显式 domain/range 等，使 LLM 无需额外学习即可理解语义。
- 采用**零样本**（zero-shot）方式，将完整本体放入系统提示（system prompt），LLM 直接生成 SPARQL 或 SQL，不依赖例子或微调。

### 关键技术细节
| 技术组件 | 描述 |
|----------|------|
| **本体设计六原则** | ① 全英文单词（如 `hasAcquisitionTime` 而非 `acqT`）；② 一致命名模式（`has<Property>`）；③ 描述性关系（如 `isSubjectOfExperiment`）；④ 显式 domain/range；⑤ 自然语言注释（标签、描述、同义词）；⑥ 无晦涩代码（有意义 URI，无自动生成 ID） |
| **迭代开发流程** | 本体、胜任力问题集（competency questions）、领域特定 prompt rider 三者共同演化：每次错误反馈到重命名属性、补充注释、调整 rider 指令，再通过测试驱动快速验证。 |
| **ETL 知识图谱构建** | 从 DICOM 头、NIfTI sidecar、实验注册系统等源提取元数据，用 Python + rdflib 映射到本体，生成约 1 千万三元组的 KG，并**物化**所有隐含关系（如逆属性、显式类成员）。 |

### 算法流程（文字描述）
1. 领域专家定义 OWL 本体（遵循六原则）。
2. 领域特定 ETL 提取元数据并生成 RDF 三元组，存入 KG（Jena Fuseki 服务）。
3. 定义胜任力问题集（NL + 参考 SPARQL + 预期结果）。
4. 测试驱动框架组合遍历：模型 × 本体表示 × 提示词 × 温度，调用 LLM 生成查询，执行并匹配结果。
5. 根据失败案例反馈迭代本体、问题集和 rider。
6. 部署时，Web 界面接收 NL 问题，生成 SPARQL，返回结果。

## 6. 论文的主要结论与发现
1. **本体设计是主导因素**：可读实体名和语义注释对准确率影响最大，超过模型选择、提示工程、温度。完整 Turtle 本体（含所有注释）达到 100%；去除注释降至 81%；用抽象标识符降至 10~14%。
2. **OWL 比 SQL DDL 有结构性优势**：SPARQL 100% vs 自动 SQL 57%。原因：① 逆属性允许双向遍历；② 显式 domain/range 减少歧义；③ 注释直接关联属性而非列；④ 实体-属性-值 三元组比宽表更易推理。
3. **MoE 模型在结构化生成任务上不如密集模型**：35B MoE 仅 57~62%准确率，远低于 27B 密集模型的 100%。
4. **量化几乎不损失精度**：Q8 和 FP8 在 SPARQL 上保持 100% 和 95%，适合本地部署。
5. **精细调优反而有害**：8B 模型 fine-tune 后准确率低于 zero-shot。
6. **最简单提示词足够**：baseline prompt 与复杂 prompt 效果相近，说明良好本体减少对提示工程的依赖。

## 7. 优点
- **方法新颖性**：将 OWL 本体主动设计为 LLM 友好型，而非被动接受现有 schema。这反转了主流 KGQA 研究（聚焦于如何适配已有混乱 schema）的思路。
- **框架完整且可复用**：端到端覆盖从本体设计、ETL、迭代测试、Web 部署，且领域无关设计（仅 ETL 需定制）。
- **实验设计严谨**：大规模消融（8 种本体表示 × 8 模型 × 多种 prompt/temp）、严格比较 SPARQL vs SQL（相同数据、相同命名、相同 LLM）、评测指标透明（结果精确匹配+容错比较）。
- **实用性突出**：全部在本地执行，使用 2020 年旧 GPU 即可部署 27B 模型并达 100% 准确率，满足医疗数据隐私要求。
- **本体设计六原则清晰可操作**：可直接被其他领域实践者采用，降低入门门槛。
- **迭代开发流程务实**：本体、问题集、rider 共同演化，通过测试驱动快速反馈，适合实际生产场景。

## 8. 不足与局限
- **测试集规模小且可能不具代表性**：仅 21 个 Query，且与本体共同演化，可能无法反映真实用户查询的多样性和复杂性。领域专家设计的“胜任力问题集”未必覆盖所有边缘情况。
- **单一领域验证**：仅神经影像学一个领域，虽声称跨领域可复用，但无实证。
- **单一模型家族**：仅评估 Qwen3，结果可能不能推广到其他架构（如 Llama、GPT）。也未测试云模型（虽有隐私限制原因）。
- **SQL 对比部分**：自动生成的 SQL schema（6 表、182 列）可能非最优设计（如宽表 vs 归一化），而手动优化 schema 可能提升 SQL 准确率。论文未探讨最优 SQL schema 设计。
- **零样本假设的小妥协**：对语法错误的 LLM 重试（fix-retry）实际上不是严格零样本，但作者指出仅较小模型触发，不过仍应提及。
- **上下文窗口限制**：完整本体约 18K tokens，在当前 32K-64K 窗口下足够。但若领域本体更复杂（>100K tokens），需依赖 token 压缩或选择更紧凑表示，可能影响准确率。
- **缺乏与其他 KGQA 方法的直接对比**：未与 AGENTiGraph、CyberBOT、GRASP 等系统在相同基准上对比，削弱了方法论优越性的说服力。
- **未见代码开源**且论文提到“intend to open source”，但当前不可复现。实验细节（如具体 prompt 内容、本体 Turtle 文件）未完全公开，复现难度较高。
